# 의예과 생물정보학 장 작성

이 저장소의 장(`chapters/wNN_*.qmd`)을 새로 쓰거나 고칠 때 따르는 규칙이다. 강의계획의 기준 문서는 `index.qmd`와 `_quarto.yml`이고, 이 스킬은 그 계획을 같은 틀의 장으로 옮기는 방법을 정한다.

## 1. 수업 구조

-   15주: W1 개론(이론) → 이론·실습 6쌍 (W2·3, W4·5, W6·7, W9·10, W11·12, W13·14), W8 중간고사, W15 기말고사
-   파일 이름: 이론 `wNN_주제.qmd`, 실습 `wNN_주제_lab.qmd` (NN은 두 자리)
-   **한 쌍 = 한 케이스.** 이론 주가 임상 케이스를 던지고 개념을 쌓는다. 다음 실습 주가 같은 케이스를 웹 도구와 R로 직접 푼다.
-   후성유전체는 W6, 단백체는 W9 안의 연결 절로 다룬다. 독립 주차를 새로 만들지 않는다.
-   주차 구성이나 케이스를 바꾸면 `index.qmd`의 표, 주차 callout, "세 가지 함정" 표도 같이 고친다.

## 2. 대상 수준

-   의예과 1–2학년. 일반생물학 정도를 들었고, 분자생물학·통계·임상 지식은 얕고, 코딩 경험은 없다고 가정한다.
-   의과학과 장(`kkonoo/BI_for_Biomed_KNUmed`의 `ko/chapters/`)을 원재료로 쓸 때는 깊이를 한 단계 낮춘다.
    -   수식, 알고리즘 내부, 도구 비교는 본문에서 빼고 `🔍 더 알아보기`로 옮기거나 지운다.
    -   임상 연결을 앞으로 당긴다. 절마다 "그래서 진료에서 무엇이 달라지나"가 보여야 한다.
-   새 개념은 이미 배운 것 위에 하나씩 올린다. 앞 주차 개념을 다시 쓸 때는 🔗로 그 절을 가리킨다.
-   임상 용어(병기, 동반진단, 이상반응 등)는 학생이 모를 수 있다. 처음 나올 때 괄호나 한 줄로 풀어 준다.

## 3. 문체

-   한국어. 형제 사이트의 한국어 장처럼 **개조식**이 기본이다: 짧은 명사형 종결("~구분", "~필요"), 인과는 `→`.
-   단, 의예과 학생에게 처음 나오는 원리는 bullet만으로 끝내지 않는다. 짧은 문단 1–3문장(한다체)으로 먼저 풀고, 그다음에 bullet로 정리한다.
-   bullet 하나에 생각 하나. 긴 문장은 나누고, 명사를 겹겹이 쌓지 않는다(`research-comms:plain-prose` 원칙).
-   전문용어
    -   한국어 용어가 교과서에 자리 잡은 것은 `한국어(영어)`로 첫 등장에 병기한다. 예: 체세포 변이(somatic variant)
    -   현장에서 영어로 부르는 것은 영어 그대로 쓴다. 예: read, count matrix, UMAP, VUS
    -   코드, 함수, 패키지, 데이터베이스 이름은 번역하지 않는다.
-   표기: 유전자 기호는 이탤릭(`*EGFR*`), 단백질과 변이 이름은 로마체(`EGFR T790M`). 별표 대립유전자는 이스케이프한다(`*CYP2C19* \*2`).
-   과장하지 않는다. 수치, 약물–유전자 짝, 지침, 승인 현황은 출처를 확인하고 쓴다. 확인하지 못한 것은 쓰지 않거나 사용자에게 표시한다.

## 4. 이론 장 구조

`templates/theory.qmd`를 그대로 따른다. 순서:

1.  front matter: `title: "WN. 제목"`, `subtitle: "이론"` (필요하면 `"이론 · 부제"`)
2.  `🚧 준비 중` callout — 장이 완성될 때까지만 둔다
3.  `🎯 학습 목표` — `callout-note collapse="true"`, "이 장을 마치면:" + 동사로 끝나는 목표 4–7개. 목표마다 대응하는 절이 있어야 한다.
4.  `🩺 오늘의 케이스` — 인용 블록. 상황 2–3줄 → 질문 한 줄(`→`) → `(🔗 WN 실습에서 직접)`
5.  번호 절
    -   `# N. 제목 이모지 {#wN-sM}` / `## M) 소제목 {#wN-sM-K}`
    -   절 맨 위에 `> 🔑 **핵심** — 한 줄`
    -   함정은 `⚠️`를 붙여 본문에, 길면 `callout-warning collapse="true"`
    -   심화는 `callout-note collapse="true" icon=false`, 제목은 `🔍 더 알아보기 — …`
    -   마지막 번호 절은 `진료에서 — 케이스로 돌아가기 🏥`. 케이스 질문에 이론으로 답할 수 있는 만큼 답하고, 직접 확인할 부분은 실습으로 넘긴다.
6.  `# 🤔 흔한 오해` — 3–5개, 번호 목록. **굵은 오해 문장?** 뒤에 줄을 바꿔 반박한다.
7.  `# ❓ 복습 문제` — 개념 3, 적용 2, 임상 시나리오 1. 정답과 해설은 바로 아래 `callout-tip collapse="true"`의 `정답과 해설`에 둔다. 시험 문제의 원형이 되므로 케이스 해석형을 꼭 넣는다.
8.  `# 📝 요약` — 절 순서대로 bullet 6–10개, ⚠️ 함정 포함
9.  `# 🔑 핵심 용어` — 5절 규칙 참고
10. `# ➕ 참고문헌` — 5절 규칙 참고

## 5. 실습 장 구조

`templates/lab.qmd`를 따른다. 순서:

1.  front matter: `title: "WN. 실습: 제목"`, `subtitle: "실습 · W(N-1) 케이스 풀기"`
2.  `🎯 학습 목표` — "이 실습을 마치면:" + 목표 3–5개
3.  `🩺 케이스 다시 보기 (🔗 [W(N-1)](...))` — 케이스 한두 줄 + `→ 오늘 목표: …`
4.  `# 0. 준비물 🧰 {#wN-s0}` — 웹 도구 링크, R 패키지 설치 코드, 데이터 파일과 출처
5.  `# K. 🌐 …` 웹 단계 (코딩 없음)
    -   무엇을 검색하고 어디를 클릭하는지 번호 순서로 쓴다. 화면이 바뀌는 곳마다 "여기서 볼 것"을 적는다.
    -   기록표(빈 표)를 주고 채우게 한다.
    -   단계 끝에 `✅ 확인 질문` 하나.
6.  `# K. 💻 …` R 단계
    -   코드는 완성본을 준다. 청크마다 앞에 "무엇을 하는 코드인지" 한 줄, 뒤에 "결과에서 볼 것" 한 줄.
    -   `🛠️ 고쳐 보기` — 기준값, 유전자, 색 같은 것을 바꿔 다시 돌리는 과제 1–2개
    -   `💡 AI 도우미에게 묻기` — 그대로 붙여 쓸 수 있는 질문 예시 1–2개
7.  `# ✍️ 제출` — 케이스에 대한 한 문단 해석. "이 결과가 말해 주는 것 / 말해 주지 않는 것"을 쓰게 한다.
8.  `# 📝 정리` — 오늘 쓴 도구·함수 표 (`| 도구 또는 함수 | 한 일 |`)
9.  `# ➕ 참고 링크`

### R 코드 규칙

-   tidyverse 스타일, 기본 파이프 `|>`. 패키지는 청크 맨 위에서 `library()`로 모두 불러온다.
-   CRAN은 `install.packages()`, Bioconductor는 `BiocManager::install()`로 준비물 절에 모아 둔다.
-   경로는 프로젝트 루트 기준 상대 경로: `data/wNN_파일이름`.
-   코드는 실행 청크(```` ```{r} ````)가 아니라 일반 코드 블록(```` ```r ````)으로 쓴다. 사이트 빌드는 코드를 실행하지 않고, 실행 청크가 하나라도 있으면 배포(GitHub Actions)에 R이 필요해진다.
-   대신 코드를 직접 R에서 돌려 확인하고, 기대 결과 그림을 `assets/img/wNN/`에 저장해 코드 바로 아래 넣는다.
-   데이터는 작게(파일당 수 MB 이내) `data/`에 둔다. 공개 자료는 출처(accession, URL)와 라이선스를, 가상 자료는 만든 스크립트(`scripts/`)를 함께 남긴다. 환자 실제 자료는 넣지 않는다.

## 6. 디자인 규칙

-   공용 테마(`assets/html.css`)는 다른 수업 사이트와 같다. 맨 위 "Subject colour" 블록 말고는 고치지 않는다. 자세한 규칙은 `COURSE_SITE_PLAYBOOK.md`.
-   제목 위계: `#` = 큰 절(왼쪽 컬러바), `##` = 소절(밑줄), `###` = 굵기만.
-   이모지: 큰 절 제목 끝에 하나. 실습 단계는 제목 앞에 종류 표시(🌐 웹, 💻 R). 본문에서는 정해진 표지(⚠️ 🔑 🔗 💡 ➡️ ✅ ❌ 🛠️)만 쓴다.
-   그림: `assets/img/wNN/` 아래에 두고 `/assets/img/wNN/파일.png`로 넣는다. 캡션은 그림이 말하는 것을 한 문장으로. 직접 그리는 도식과 그래프는 다시 만들 수 있게 `figs/` 스크립트로 남긴다(처음 만들 때 `kkonoo/BI_for_Biomed_KNUmed`의 `figs/style.py`를 가져와 색과 글꼴을 맞춘다).
-   시뮬레이터(edu_sims)는 iframe으로 넣는다. 높이와 테마는 `assets/edu-sims-resize.html`이 맞춘다.
-   교차 링크: `🔗 [W2 §4](w02_rare_disease.qmd#w2-s4)`.

### 핵심 용어 표

```markdown
| 용어 | 한 줄 설명 |
|---|---|
| Variant of uncertain significance (VUS) | 병적인지 양성인지 근거가 부족해 판단을 보류한 변이 |
| Somatic variant (체세포 변이) | 수정 이후 특정 조직에서 생겨 자손에게 전달되지 않는 변이 |
```

-   왼쪽 열은 표준 표기. 본문에서 한국어 용어로 쓴 것은 괄호에 한국어를 넣는다. `assets/key-terms.html`이 괄호 안 약어와 한국어를 별칭으로 읽어, 본문 첫 등장에 마우스를 올리면 뜻이 뜬다.
-   표에 넣은 용어는 본문에 실제로 나와야 한다. 정의는 한 줄, 의예과 학생이 읽고 이해할 수 있는 말로.

### 참고문헌

-   `###` 소제목으로 묶는다. 형식: `저자. [*제목.*](https://doi.org/…) 저널. 연도.`
-   실제로 있는 문헌만 넣는다. DOI나 PubMed로 확인하고, 확인하지 못한 문헌은 넣지 않는다.
-   리뷰와 지침을 먼저, 원 논문은 핵심만. 데이터베이스는 공식 페이지 링크.

## 7. 작업 순서

1.  `index.qmd`의 해당 주차 callout과 장의 🚧 개요를 읽는다. 개요의 절 구성이 출발점이다. 구성을 바꾸면 이유를 말한다.
2.  원재료를 모은다.
    -   오믹스 개념: `kkonoo/BI_for_Biomed_KNUmed`의 `ko/chapters/`
    -   임상 GWAS·PRS·단백체·단일세포 심화: `kkonoo/advanced_BI_for_MD_PhD_KNUmed`
    -   RNA-seq 실습 코드: `kkonoo/BI_for_MD_PhD_KNUmed`
    -   옛 학부 자료(케이스, 흔한 오해, 복습 문제): Google Drive `교육/[기타] 학부 생물정보학/course_materials`
3.  본문을 쓴다 → 수치·약물·지침을 확인한다 → 흔한 오해, 복습 문제, 요약, 핵심 용어, 참고문헌을 채운다.
4.  실습 장은 코드를 실제로 돌려 보고 그림을 저장한다.
5.  `🚧 준비 중` callout을 지우고 `quarto render`로 확인한다. 링크, 앵커, 그림, 라이트·다크 모드, 모바일 폭을 본다.

## 8. 완성 체크리스트

-   [ ] 학습 목표마다 대응하는 절이 있다.
-   [ ] 의예과 학생이 모를 용어는 첫 등장에 풀이가 있다.
-   [ ] `index.qmd` "세 가지 함정" 표의 이 주차 칸(집단 차이, 우연과 다중검정, 연관 ≠ 인과)이 본문에 나온다.
-   [ ] 수치, 약물–유전자 짝, 지침, 참고문헌을 확인했다.
-   [ ] 앵커는 `{#wN-sM}` 형식이고 깨진 링크가 없다.
-   [ ] 핵심 용어 표의 용어가 본문에 실제로 나온다.
-   [ ] 실습 코드는 실제로 돌아가고, 데이터 출처가 적혀 있다.
-   [ ] `🚧 준비 중` callout을 지웠고, 렌더가 경고 없이 끝난다.
